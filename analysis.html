Phase 5: Technical Analysis & Defense Questions

Q1: Micro-Architectural Root Cause of False Sharing

Variant 1 suffers a 6.74x slowdown because all elements of hit_count reside on a single 64-byte L1 cache line. Under the MESI protocol, whenever Core A increments its index, the line state transitions to Modified, sending a BusRdX invalidation signal, causing Cores B-H to reload from L2/L3.

Q2: Hyperthreading (SMT) Saturation

Speedup scaled up to 8 physical cores (6.08x), but experienced diminishing returns at 16 SMT threads (7.56x vs theoretical 8.30x). SMT threads share ALUs and caches per core. Collatz is ALU-bound without memory stalls, so hardware execution pipelines were saturated at 8 cores.

Q3: Empirical vs. Theoretical Amdahl Discrepancy

Amdahl assumes zero communication overhead. At k=16, empirical speedup fell short due to OpenMP thread creation and barrier synchronization overheads, as well as L3 cache contention.

Q4: The Scheduling Trade-Off Dilemma

At dynamic(100), atomic lock contention on the global queue added overhead. Lock contention surpassed benefits when chunk size dropped below 1000. schedule(guided) provided the best balance.
